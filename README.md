# 발자취 (足あと) — 전단지 배포 팀 실시간 지도

여러 명이 같은 동네를 돌며 우편함에 전단지를 넣을 때, **누가 어디를 돌았고 어디가 겹치는지**를 지도에서 바로 보이게 하는 앱입니다.
播磨町(兵庫県加古郡) 작업을 위해 만들었지만 일본 전역에서 그대로 쓸 수 있습니다.

- 서버 없이도 동작하는 모바일 웹앱(PWA). 설치 없이 링크만 열면 됩니다.
- 기본 지도는 구글·네이버 지도처럼 읽기 쉬운 **OpenFreeMap 벡터 지도**(무료·키 없음·제한 없음), 예비로 地理院タイル. 지도 글자는 설정에서 일본어 / 한국어 / 한국어+일본어 선택 (한국어 이름은 OSM에 등록된 역·시설·지명만). 건물·길 데이터는 OpenStreetMap. 라이선스 검토는 [LICENSES.md](LICENSES.md).
- 팀 공유는 Firebase 무료 플랜 하나면 충분합니다.

## 현장 고찰 → 기능

| 겪은 문제 | 해결 |
|---|---|
| 동선이 겹친다 | 구역을 그려 팀원별로 색 배정. 구역 안의 **길이 선분 단위로 완료 표시**되어 누가 어디를 돌았는지 보임 |
| 서로 위치를 몰라 전화 | 같은 세션 코드로 접속하면 **실시간 위치·발자취** 공유. 90초 이상 수신 없으면 "오프라인" 표시 |
| 이미 돈 길을 또 돈다 | 남이 지나간 자리(기본 15m)에 들어가면 **진동 + 경고**, 겹친 구간은 빨간 점선, 겹친 거리 누적 |
| 골목마다 집이 몇 동인지 | 국토지리원 건물(전수)을 **가장 가까운 골목에 붙여** 골목마다 "집 n동". 집은 점으로 그려지고, 그 골목을 처음 지나간 사람 색으로 바뀜 |
| 왕복한 기록이 남는지 | 골목 선분마다 **누가 몇 시에 몇 번 지나갔는지** 저장 (45초 넘게 떠났다 오면 새 통과). 길을 길게 누르면 말풍선으로 표시, 많이 지나간 길은 굵어짐 |
| 얼마나 걸었고 몇 장 넣었나 | 상단에 **km · 걸음 수(보폭 설정) · 전단 ≈n** 실시간 표시. 전단 수 = 내가 처음 지나간 골목에 면한 집(아파트는 세대) 수 |
| 작업량을 모른다 | 구역마다 OSM 건물 데이터로 **세대수 추정** + 길 길이 + **예상 소요 시간**(徒歩80m/分 기준). e-Stat 값으로 수동 보정 가능 |
| 다음 사람이 헛걸음 | 🚫 チラシお断り · 🔒 오토락 · ✅ 집합우편함 완료 · 📝 메모 를 지도에 남겨 팀 전체가 공유 |
| 기록이 안 남는다 | 세션별로 구역·궤적·완료 상태를 기기에 저장. JSON/GeoJSON 내보내기·불러오기 |
| GPS가 튄다 | 정확도 60m 초과 점 버림, 8m/s 초과 점프 버림, 3m 미만 이동 무시 |
| 통신이 끊긴다 | 오프라인 우선: 궤적은 먼저 기기에 저장, 최근 본 지도 타일은 캐시. 복구되면 묶어서 전송 |
| 화면이 꺼진다 | 기록 중 Wake Lock으로 화면 유지 |

## 화면 조작

- **👁 표시 켜기/끄기**: 경로 · 회전 지점/출발·도착 · 내 발자취 · 팀원 발자취 · 골목(완료 색) · 집 점 · 표시 · 구역 테두리 · 팀원 위치 를 각각 켜고 끌 수 있고 기억됩니다. 안내만 보고 걸을 땐 발자취·집 점을 끄면 깔끔합니다.
- **◎ 따라가기**: 한 번 누르면 내 위치로 이동하고 계속 화면 중앙에 유지. 지도를 손으로 움직이면 해제, 다시 누르면 다시 켜짐.
- **안내 바**: "여기서 재계산"(남은 골목만으로 현재 위치에서 다시), "경로 숨기기/보이기", "접기"(한 줄로). 접힌 바를 탭하면 펼쳐짐.
- 구역 편집의 "내 위치에서 바로"는 출발점 탭 없이 즉시 경로를 만들고 따라가기를 켭니다.

## 사용 방법 (팀원)

1. 링크를 열고 **이름·색·세션 코드**를 입력합니다. 세션 코드는 팀 전체가 같은 것을 씁니다 (예: `1013-A`).
2. 홈 화면에 추가(PWA)하면 앱처럼 열립니다.
3. 리더가 **구역**(▰ 버튼)을 그리고 담당자를 배정합니다. 구역을 만들면 세대수·소요 시간이 자동 추정됩니다.
4. 각자 **▶ 기록 시작**. 걸은 길이 색으로 남고, 구역 안의 길은 지나가면 완료(굵은 선)로 바뀝니다.
5. 현장 정보는 📍 로 남깁니다. 경고가 뜨면 그 길은 이미 다른 사람이 지나간 길입니다.
6. 끝나면 **■ 기록 정지**. 정지하면 위치 공유도 멈춥니다.

## 배포 (무료)

### 1) 정적 호스팅 — GitHub Pages
이 폴더를 저장소에 올리고 Settings → Pages → Branch `main` / root 로 켜면 `https://<계정>.github.io/<저장소>/` 로 열립니다.
HTTPS 라서 위치 정보·PWA·Wake Lock 이 모두 동작합니다. (Netlify, Cloudflare Pages 도 동일)

올리기 전에 커밋 작성자 이메일을 GitHub noreply 주소로 바꿔 두면 개인 이메일이 공개되지 않습니다 (GitHub → Settings → Emails 에서 `숫자+아이디@users.noreply.github.com` 확인):
```bash
git config user.email "ID+listenpyo@users.noreply.github.com"
```

### 2) 팀 공유 — Firebase Realtime Database (무료 Spark 플랜)
기본값(설정 → "이 기기 안에서만")은 서버 없이 같은 기기의 탭끼리만 공유되는 테스트 모드입니다. 팀 공유는:

1. https://console.firebase.google.com 에서 프로젝트 생성 → **Realtime Database** 만들기 (지역: asia-southeast1 또는 가까운 곳).
2. 프로젝트 설정 → 웹 앱 추가 → `firebaseConfig` 객체를 복사.
3. 데이터베이스 **규칙**을 아래로 바꿉니다 (세션 코드를 모르면 접근 불가, 세션 당 쓰기만 허용):
   ```json
   {
     "rules": {
       "sessions": {
         "$code": {
           ".read": "$code.length >= 4",
           ".write": "$code.length >= 4",
           "members": { "$id": { ".validate": "newData.hasChildren(['id','name','t'])" } }
         }
       }
     }
   }
   ```
   (익명 인증을 붙이면 더 안전합니다. 세션 코드를 길고 추측 어려운 것으로 쓰는 것이 1차 방어선입니다.)
4. 앱 설정 → 실시간 공유 방식 → Firebase → `firebaseConfig` 를 JSON 으로 붙여넣기 → 적용. (키 이름에 따옴표가 필요합니다: `{"apiKey": "...", "databaseURL": "...", ...}`)
5. 팀원 모두 같은 설정을 넣습니다. 한 번 넣으면 기기에 저장됩니다.

Firebase 무료 한도(동시 접속 100, 저장 1GB, 월 다운로드 10GB)는 수십 명 규모 팀의 하루 작업에 충분합니다. 작업이 끝난 세션은 콘솔에서 `sessions/<코드>` 를 지워 개인정보를 남기지 않습니다.

### 3) 로컬 실행 (개발)
```bash
python -m http.server 8787
```
→ http://localhost:8787 . 설정에서 "테스트: 지도를 탭하면 내 위치로 간주"를 켜면 PC에서도 걷는 것을 흉내낼 수 있고, 팀 탭의 "데모 팀원 추가"로 가상 팀원이 돌아다닙니다. 탭을 두 개 열면 서로 보입니다.

## 추정 로직의 한계 (현장에서 보정하세요)

- 건물 윤곽은 **국토지리원 基盤地図情報**(전국 전수)를 1차로 쓰고, OSM 은 태그(공동주택·층수)가 있을 때만 보조로 씁니다. 播磨町 표본에서 OSM 은 실제 건물의 약 53%만 입력돼 있었습니다 — 한국에서 빌라·원룸이 지도에 빠지는 것과 같은 문제라, OSM 만 믿으면 안 됩니다.
- 일본의 원룸·빌라에 해당하는 **アパート**(2층 목조 4~8세대)는 지리원 데이터에서 단독주택과 같은 "普通建物"로만 나옵니다. 앱은 바닥면적 130~400㎡ + 가늘고 긴 형태를 "アパート 의심"으로 따로 세고 지도에 주황 동그라미로 표시합니다. 현장에서 집합우편함을 보고 동그라미를 탭해 ✅ 표시(세대수 메모)를 남기세요.
- 길도 **국토지리원 도로중심선**(전수)을 1차로 씁니다. OSM 은 길 이름을 빌리는 데만 쓰는데, 일본 주택가 골목은 OSM 에도 이름이 거의 없어 "이름 없는 길"로 나옵니다. 길 선분은 30m 이하로 잘라 일부만 걷고 전체가 완료되지 않게 합니다.
- 지리원 데이터까지 못 받으면 OSM 건물·길, 그것도 없으면 **길 길이 100m 당 15세대**로 계산합니다. e-Stat 소지역 세대수를 "직접 입력"에 넣으면 그 값이 우선합니다.

## 4인 시뮬레이션 결과 (2026-10-13, 播磨町 南野添 주택가 250m×270m)

실제 골목 데이터 위에서 원격 팀원 3명 + 나 를 걷게 한 테스트. 설정 → "테스트: 지도를 탭하면 내 위치로 간주" 를 켜고 콘솔에서 재현 가능.

| 항목 | 결과 |
|---|---|
| 구역 데이터 | 길 397조각 4,949m · 집 207동 (전부 골목에 배정) · 추정 291세대 · 예상 148분 |
| 처리 성능 | 4명분 2,200여 점 처리 772ms (폰에서도 실시간에 충분) |
| GPS 필터 | 정확도 150m 점 1개, 500m 점프 1개 → 둘 다 제외됨 |
| 완료율 | 4명이 나눠 돌아 397/397 길, 207/207 집 완료 |
| 집·전단 배분 | 집 30+48+62+67 = 207 (중복 0), 전단 40+96+88+67 = 291 (= 추정 세대수) |
| 왕복 기록 | 한 골목을 처음 1회 + 왕복 3회 → **통과 4회** 시각과 함께 기록 |
| 겹침 경고 | 남이 먼저 돈 골목에 들어가자 경고. 겹친 거리 857m (구역을 경도로 기계적으로 4등분해 경계 골목이 겹친 것 — 실제로도 이렇게 나눠 걸으면 겹친다는 뜻) |
- 공동주택 세대수는 바닥면적×층수÷65㎡(アパート는 ÷32㎡) 근사입니다.
- 길 완료 판정은 반경 12m(설정 변경 가능). 좁은 골목이 나란히 있으면 옆 골목도 완료로 잡힐 수 있어, 길을 탭해서 수동으로 되돌릴 수 있습니다.

## 경로 안내 (우편배달부 문제) · n명 분할 · 시뮬레이션

구역 편집 → **📍 출발점 핀** (지도 탭, 드래그로 조정) → **🏁 집결지 핀** (선택) → **인원 수** → **🧭 경로 만들기** → 아직 안 돈 골목을 **인원 수만큼 나눠, 같은 출발점에서 출발해 집결지에 모이는 경로**가 사람 수만큼 색을 달리해 그려집니다. 각 경로에 담당자를 지정하면(접속 중인 팀원 자동 배정) 그 사람 화면에만 회전 안내가 뜹니다. 핀을 드래그하면 경로가 자동으로 다시 계산됩니다.

- **▶ 동시 이동 시뮬레이션**: n명이 각자 경로를 동시에 걷는 모습을 ×10/×30/×100 배속으로 재생. 누가 몇 분에 집결지에 닿는지, 경로가 어디서 교차하는지 미리 볼 수 있습니다.
- 안내 중 "여기서 재계산"은 내 경로에 남은 골목만으로 현재 위치에서 다시 만듭니다 (다른 사람 경로는 그대로).
- 분할 알고리즘: 전체 한붓그리기 경로를 만든 뒤 n조각으로 자르고, 각 조각의 앞뒤를 출발점·집결지와 최단경로로 이은 다음, 조각 경계를 움직여 **가장 오래 걷는 사람의 거리를 최소화**(Frederickson 휴리스틱). 테스트(골목 2.85 km): 1명 4.16 km → 2명 2.32 km → 3명 1.72 km → 4명 1.43 km (각자 거리 편차 ±10% 이내).

- 알고리즘: 지리원 도로중심선을 그래프로 만들고(교차점·T자 틈 보정), 떨어진 덩어리는 최단경로로 잇고, 홀수 차수 노드(막다른 골목·T자)를 최단경로 거리로 짝지어(greedy + 2-opt) 한 번 더 걷게 한 뒤 Hierholzer 로 한붓그리기. 출발점은 고정, 도착점은 중복이 가장 적은 곳으로 자동 선택. [js/route.js](js/route.js)
- 테스트(南野添 블록, 골목 150조각 2.87km): 경로 4.14km(돌아야 할 길 2.85km + 이동만 1.29km), 회전 98회(유턴 25 — 막다른 골목 수만큼은 불가피), 계산 18ms. 경로대로 걷는 시뮬레이션에서 150조각 중 149 완료(1개는 구역 가장자리의 16m 고립 토막, 경고로 알려줌).
- 한계: 막다른 골목이 많은 일본 주택가에서는 "이동만 하는 구간"이 30~45% 나옵니다. 이건 어떤 경로로 돌아도 피할 수 없는 왕복분이고, 앱은 그 왕복을 가장 짧게 묶습니다.
